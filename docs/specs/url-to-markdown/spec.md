# URL → Markdown 변환 후 LLM으로 넘기기

웹 페이지 URL을 붙여 넣으면 본문만 Markdown으로 추출해 보여 주고, 그 결과를 복사·다운로드하거나 ChatGPT·Claude 새 대화로 바로 넘기는 단일 화면 서비스입니다. 동작은 https://www.feedme.wiki/ 를 참고하되, 아래 수용 기준이 다르게 정한 부분은 이 스펙을 따릅니다.

## 연결된 소스

- [prototype.html](prototype.html) — 승인된 화면 구성, 요소 배치와 순서, 상태별 화면(빈 상태, 변환 중, 결과, 프롬프트 입력, 잘못된 URL, 가져오기 실패, 본문 없음), 문구, 다크·라이트 테마와 좁은 화면 배치를 정합니다. 화면 위 검은 리뷰 바는 제품이 아닙니다.
- [docs/decisions/ui-composition.md](../../decisions/ui-composition.md) — 화면을 shadcn 공식 컴포넌트와 semantic token으로 구성하는 기준을 정합니다.
- [docs/decisions/dependency-versions.md](../../decisions/dependency-versions.md) — 새로 추가하는 의존성(defuddle 등)의 버전 범위 기준을 정합니다.

## 사용자가 얻는 결과

- URL 하나로 웹 페이지의 본문만 담긴 Markdown을 얻고, 렌더링된 모습과 원문 Markdown을 오가며 확인합니다.
- 그 Markdown을 프롬프트와 함께 복사하거나, `.md` 파일로 내려받습니다.
- 버튼 한 번으로 ChatGPT나 Claude 새 대화를 열고, 원하면 프롬프트를 본문 앞에 붙여 보냅니다.
- `?url=` 링크로 열면 바로 변환되므로 결과를 공유하거나 북마크할 수 있습니다.
- 라이트·다크 모드를 직접 바꿉니다.

## 범위

- 단일 페이지 하나에 워드마크와 태그라인, URL 입력, 결과, 내보내기, 테마 토글, 푸터가 있습니다.
- 한 번에 URL 하나를 변환합니다.
- 계정, 기록, 저장 기능은 없습니다.

## 수용 기준

### 화면 구성

1. 상단 오른쪽에 테마 토글이 있고, 그 아래 "FEED-ME" 워드마크와 "어떤 URL이든, Markdown으로." 태그라인, URL 입력칸이 순서대로 놓입니다.
2. 변환 전에는 입력칸 아래에 아무 안내 카드도 없습니다.
3. 하단 푸터에 "© 2026 feed-me · Feedback · GitHub"가 있습니다. Feedback은 이 저장소의 새 이슈 페이지를, GitHub는 이 저장소를 새 탭에서 엽니다.

### 입력

4. URL 입력칸 안에 지우기(✕) 버튼과 가져오기(→) 버튼이 있습니다. 지우기 버튼은 입력값이 있을 때만 보이고, 가져오기 버튼은 입력값이 비어 있으면 비활성화됩니다.
5. 가져오기 버튼과 입력칸에서 Enter 둘 다 변환을 시작합니다.
6. 빈 입력칸(또는 선택 영역을 덮어써서 결과가 URL 하나가 되는 경우)에 올바른 URL을 붙여넣으면 버튼을 누르지 않아도 곧바로 변환을 시작합니다. URL이 아닌 텍스트를 붙여넣으면 변환하지 않고 입력만 됩니다.
7. `http://` 또는 `https://`로 시작하는 주소 형식이 아닌 값으로 변환을 시도하면 변환하지 않고, 입력칸을 오류 상태로 표시한 뒤 아래에 "http:// 또는 https://로 시작하는 웹 페이지 주소를 입력해 주세요."를 보여 줍니다. 입력을 고치기 시작하면 오류 표시가 사라집니다.
8. 지우기를 누르면 입력값, 결과, 프롬프트, 열린 패널이 모두 사라지고 처음 상태로 돌아가며, 주소창의 `?url=`도 지워지고 입력칸에 포커스가 갑니다. 변환 중에 눌러도 진행 중인 결과는 화면에 나타나지 않습니다.

### 링크로 바로 변환

9. 페이지를 `?url=<인코딩된 URL>`과 함께 열면 그 URL이 입력칸에 채워지고 곧바로 변환이 시작됩니다.
10. 변환을 시작하면 주소창이 `?url=<인코딩된 URL>` 형태로 바뀝니다. 이 주소를 새 창에서 열면 같은 페이지가 다시 변환됩니다.

### 변환

11. 변환 중에는 가져오기 버튼이 스피너로 바뀌고 비활성화되며, 결과 자리에 스켈레톤이 보입니다.
12. 본문 추출은 defuddle 라이브러리로 하고, 결과는 Markdown입니다.
13. 페이지를 가져오지 못하면(네트워크 오류, 4xx·5xx 응답 등) "페이지를 가져오지 못했습니다" 경고와 "다시 시도" 버튼을 보여 줍니다.
14. 페이지는 가져왔지만 추출된 본문이 비어 있으면 "본문을 찾지 못했습니다" 경고와 "다시 시도" 버튼을 보여 줍니다. (feedme.wiki는 이때 제목만 보여 주지만, 이 스펙은 경고를 보여 줍니다.)
15. "다시 시도"는 현재 입력칸의 URL로 변환을 다시 시작합니다.

### 결과 확인

16. 결과 머리에는 페이지 제목, 저자, 사이트명, 원문 링크가 보입니다. 저자가 없으면 사이트명만, 저자와 사이트명이 같으면 한 번만 보여 줍니다. 원문 링크는 새 탭에서 열립니다.
17. 본문 위에 "미리보기"와 "Markdown" 탭이 있고, 변환할 때마다 "미리보기"가 선택된 상태로 시작합니다.
18. "미리보기"는 렌더링된 모습(제목, 목록, 링크, 인용, 코드 블록, 표)을 보여 줍니다. 긴 코드 블록과 넓은 표는 페이지 전체가 아니라 그 요소 안에서 가로로 스크롤됩니다.
19. "Markdown"은 복사·다운로드되는 것과 같은 원문 Markdown 텍스트를 고정폭 글꼴로 보여 주고, 긴 내용은 그 영역 안에서 스크롤됩니다.

### 내보내기

20. 결과 머리 오른쪽에 "복사하기" 버튼과 그 옆 ∨(열기 옵션) 버튼이 한 덩어리로 붙어 있습니다.
21. "복사하기"를 누르면 클립보드에 텍스트가 들어가고, 버튼이 잠시 "복사됨"으로 바뀌며 확인 토스트가 뜹니다. 프롬프트가 비어 있지 않으면 복사 텍스트는 "프롬프트 + 빈 줄 + Markdown"이고, 비어 있으면 Markdown만입니다.
22. 프롬프트가 비어 있지 않은 동안 "복사하기" 버튼 아래에 "프롬프트 포함"이 보입니다.
23. ∨를 누르면 "마크다운 다운로드", "ChatGPT에서 열기", "Claude에서 열기" 메뉴가 열립니다. 메뉴 밖을 누르거나 Esc를 누르면 닫히고, 항목을 고르면 실행 후 닫힙니다.
24. "마크다운 다운로드"는 Markdown 본문만 담긴 `.md` 파일을 내려받습니다(프롬프트는 넣지 않습니다). 파일 이름은 페이지 제목을 바탕으로 만듭니다.
25. "ChatGPT에서 열기"와 "Claude에서 열기"는 각 서비스의 새 대화를 새 탭에서 엽니다. 보낼 텍스트는 복사와 같은 규칙(프롬프트가 있으면 "프롬프트 + 빈 줄 + Markdown")입니다.
26. 보낼 텍스트가 URL 전달 한도 이하이면 그 텍스트가 새 대화 입력창에 들어간 상태로 열리고, 그 사실을 토스트로 알립니다.
27. 한도를 넘으면 같은 텍스트 전체를 클립보드에 복사한 뒤 새 대화를 열고, "본문이 길어 클립보드에 복사했습니다. 새 대화에 붙여넣기(Ctrl+V) 하세요." 취지의 토스트를 띄웁니다. 본문을 잘라 보내지 않습니다.

### 프롬프트

28. 결과 아래에 "+ 프롬프트 추가하기" 버튼이 있고, 처음에는 접혀 있습니다. 누르면 여러 줄 입력칸과 프리셋 칩 "요약해줘", "한국어로 번역해줘", "쉽게 설명해줘"가 펼쳐지고 입력칸에 포커스가 갑니다. 다시 누르면 접힙니다.
29. 프리셋 칩을 누르면 입력칸 내용이 그 문구로 바뀌고, 사용자는 이어서 자유롭게 고쳐 쓸 수 있습니다. 입력칸 내용이 어떤 프리셋 문구와 정확히 같을 때만 그 칩이 선택된 모양으로 보입니다.
30. 입력칸에 내용이 있으면 입력칸 안에 지우기(✕) 버튼이 보이고, 누르면 내용이 비워집니다.
31. 프롬프트를 접어도 내용은 유지되고 복사·열기에 계속 쓰입니다. 공백만 있는 프롬프트는 없는 것으로 봅니다.
32. 프롬프트는 어디에도 저장하지 않습니다. 새로고침하거나 지우기를 누르면 사라지고, 복사나 열기 후에는 그대로 남습니다.

### 테마와 화면 크기

33. 처음 방문하면 다크 모드로 보입니다. 상단 토글로 라이트와 다크를 바꾸며, 모든 상태가 두 테마에서 읽을 수 있게 보입니다.
34. 좁은 화면(390px 폭)에서는 복사 버튼 묶음이 제목 아래로 내려가 가로로 넓게 펼쳐지고, 어떤 action도 숨기지 않습니다.

## 확정된 제약과 이유

- **본문 추출은 defuddle을 씁니다.** 사용자가 필수로 지정했습니다. 확인한 내용: 0.19.6을 bun과 linkedom으로 서버 쪽에서 돌려 Wikipedia, react.dev 블로그, Hacker News에서 제목과 Markdown 본문을 얻었습니다(`Defuddle(document, url, { markdown: true })`). defuddle은 HTML을 직접 가져오지 않으므로 페이지 HTML은 앱이 가져와 넘겨야 하고, DOM 구현(linkedom 또는 JSDOM)이 필요합니다. 공식 문서는 `defuddle/node`를 쓰려면 `"type": "module"`이 필요하다고 적고 있습니다.
- **긴 본문은 URL 대신 클립보드로 넘깁니다.** 사용자가 정했습니다. 테스트한 기사들의 Markdown이 6,000–34,000자여서 URL에 모두 실으면 열리지 않거나 잘릴 가능성이 큽니다. feedme.wiki는 9만 자 안팎도 그대로 `?q=`에 싣지만 따르지 않습니다. "항상 클립보드", "항상 URL", "원문 URL만 전달"은 기각했습니다.
- **내보내기는 복사를 주 버튼으로 한 스플릿 버튼입니다.** 사용자가 feedme.wiki를 따라 정했습니다.
- **프롬프트는 접히는 자유 입력칸이고, 프리셋은 그 입력칸을 채우는 칩입니다.** 사용자가 feedme.wiki를 따라 정했습니다. 별도의 "직접 입력" 칩은 두지 않습니다.
- **프롬프트는 복사와 LLM 열기에 포함되고, 다운로드에는 포함되지 않습니다.** 사용자가 정했습니다.
- **`?url=` 링크 변환, 미리보기/Markdown 탭, 붙여넣기 자동 변환을 넣습니다.** 사용자가 상용 서비스(Jina Reader, defuddle.md 등)를 참고해 골랐습니다. 단어·토큰 수 표시는 고르지 않았습니다.
- **워드마크·태그라인·푸터 구성과 다크 기본 테마는 feedme.wiki를 따릅니다.** 사용자가 정했습니다.

## 가정 (바꿔도 되는 기본값)

- URL 전달 한도는 보낼 텍스트 6,000자(인코딩 전)로 둡니다. 실제 한도는 확인하지 못했습니다(아래 위험 참고).
- ChatGPT는 `https://chatgpt.com/?q=<텍스트>`, Claude는 `https://claude.ai/new?q=<텍스트>` 형태로 엽니다. feedme.wiki의 ChatGPT 링크가 이 형태임을 확인했습니다.
- 저자가 없을 때는 사이트명으로 대신합니다(react.dev, HN에서 저자가 비어 있었습니다).
- 사용자가 토글로 고른 테마는 다음 방문에도 유지합니다.
- 변환을 시작할 때 주소창은 기록을 쌓지 않고 현재 항목을 바꿉니다(뒤로 가기로 이전 변환을 오가지 않습니다).
- 푸터 Feedback은 `https://github.com/yeom0823/feedme-clone/issues/new`, GitHub는 `https://github.com/yeom0823/feedme-clone`으로 연결합니다.
- 프롬프트의 "1회용"은 "저장하지 않음"(새로고침·지우기 때 사라짐)으로 해석합니다.

## 범위 밖과 이유

- 로그인이 필요하거나 JavaScript로만 본문을 그리는 페이지의 추출 — 페이지 HTML만 받아 defuddle에 넘기므로 지원하지 않습니다. 이 경우 "본문 없음" 또는 "가져오기 실패"로 안내합니다.
- 변환 기록, 프롬프트 저장, 계정 — 요청 범위 밖이고, 프롬프트는 저장하지 않기로 정했습니다.
- ChatGPT·Claude 외 다른 LLM으로 열기, 단어·토큰 수 표시 — 요청 범위 밖이거나 고르지 않았습니다.
- 경로 접두어 방식(`서비스주소/https://…`) — `?url=` 방식만 넣기로 했습니다.
- 요청 제한, SSRF 방어 같은 보안 하드닝 — 프로젝트 검증 예산(AGENTS.md)상 스펙이 요구하지 않은 하드닝은 범위 밖입니다.

## 남은 위험

- **URL 전달 한도와 `?q=` 동작을 확인하지 못했습니다.** 회사 네트워크가 chatgpt.com과 claude.ai의 TLS 연결을 막아 curl로 측정할 수 없었습니다. 실제 한도가 6,000자보다 작으면 짧은 글도 열리지 않을 수 있고, 서비스가 `q` 파라미터를 바꾸면 입력창이 비어 있을 수 있습니다. 구현 시 열 수 있는 네트워크에서 두 서비스를 직접 열어 확인하고, 필요하면 한도 값을 조정합니다.
- **`"type": "module"` 요구.** 현재 프로젝트 `package.json`에는 `type` 필드가 없습니다. Next.js 번들링 아래에서 `defuddle/node` import가 그대로 되는지 확인하지 않았습니다.
- **클립보드 쓰기 제한.** 브라우저는 사용자 동작 안에서만 클립보드 쓰기를 허용합니다. 긴 본문을 클립보드로 넘기는 경로는 메뉴 클릭 직후에 복사와 새 탭 열기가 이뤄져야 합니다.
- **`?url=`로 열 때 아무 주소나 서버가 가져옵니다.** 공유된 링크로 의도치 않은 주소를 변환할 수 있지만, 하드닝은 범위 밖이라 그대로 둡니다.
- 일부 사이트는 서버에서 보낸 요청을 막거나 다른 HTML을 돌려줄 수 있습니다.
