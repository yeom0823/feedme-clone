# 변환한 글 저장하고 다시 보기

로그인한 사용자가 변환 결과를 저장해 두고, "저장한 글" 목록에서 골라 다시 볼 수 있게 합니다. 저장하는 것은 URL이 아니라 저장한 시점의 변환 결과 전체이므로, 원문이 바뀌거나 사라져도 저장한 내용을 그대로 다시 볼 수 있습니다.

이 스펙은 [url-to-markdown](../url-to-markdown/spec.md)이 범위 밖으로 둔 "저장 기능"을 로그인 사용자에 한해 엽니다. 변환, 결과 확인, 내보내기, 프롬프트의 기존 동작은 그 스펙을 그대로 따릅니다.

## 연결된 소스

- [prototype.html](prototype.html): 승인된 화면 구성을 정합니다. 화면은 홈(변환 결과), 저장한 글, 저장한 글 보기, 로그인 안내 네 가지입니다. 버튼 위치, 상태별 화면(저장 전, 저장됨, 로그아웃, 빈 목록, 삭제 확인), 문구, 좁은 화면 배치도 이 파일이 정합니다. 화면 위 검은 리뷰 바는 제품이 아닙니다.
- [docs/specs/url-to-markdown/spec.md](../url-to-markdown/spec.md): 결과 머리, 미리보기/Markdown 탭, 내보내기(복사, 다운로드, ChatGPT·Claude 열기)의 동작을 정합니다. 저장한 글 보기도 이 규칙을 그대로 씁니다.
- [docs/decisions/ui-composition.md](../../decisions/ui-composition.md): 화면을 shadcn 공식 컴포넌트와 semantic token으로 구성하는 기준을 정합니다.
- [docs/decisions/dependency-versions.md](../../decisions/dependency-versions.md): 새 의존성을 추가할 때의 버전 범위 기준을 정합니다.

## 사용자가 얻는 결과

- 변환한 글을 버튼 한 번으로 내 계정에 저장합니다.
- 헤더의 "저장한 글"에서 지금까지 저장한 글을 최근 순으로 봅니다.
- 저장한 글을 열면 변환 직후와 같은 결과 화면(탭, 내보내기)으로 다시 보고, 원문 페이지를 다시 가져오지 않습니다.
- 더 필요 없는 글은 삭제합니다.

## 범위

- 저장 버튼, 저장한 글 목록, 저장한 글 보기, 삭제를 다룹니다.
- 저장은 로그인한 사용자만 할 수 있고, 각 사용자는 자기가 저장한 글만 봅니다.
- 같은 URL은 사용자당 하나만 저장됩니다.

## 수용 기준

### 헤더

1. 로그인 상태에서는 홈, 저장한 글, 저장한 글 보기 화면의 헤더에 "저장한 글"과 "설정" 링크가 있습니다. 로그아웃 상태에서는 "로그인" 링크만 있습니다.
2. "저장한 글"을 누르면 저장한 글 목록으로 갑니다.

### 저장

3. 변환 결과가 보이면 결과 머리 오른쪽, "복사하기" 스플릿 버튼 왼쪽에 "저장" 버튼이 있습니다. 가져오기 실패, 본문 없음, 변환 중일 때는 보이지 않습니다.
4. 로그인 상태에서 "저장"을 누르면 그 결과가 내 저장한 글에 추가되고, 버튼이 "저장됨"(체크 아이콘)으로 바뀌며 "저장했습니다" 토스트가 뜹니다.
5. 저장되는 내용은 누른 시점의 제목, 저자, 사이트명, 원문 URL, Markdown 본문과 저장 시각입니다. 프롬프트는 저장하지 않습니다.
6. 이미 저장한 URL을 변환하면 처음부터 "저장됨"으로 보입니다. "저장됨"을 눌러도 아무 일도 일어나지 않고, 목록에 같은 글이 두 번 생기지 않습니다.
7. 로그아웃 상태에서 "저장"을 누르면 로그인 화면으로 갑니다. 이때 로그인 화면에 "글을 저장하려면 로그인이 필요합니다. 로그인하면 보던 글로 돌아갑니다." 안내가 보입니다.
8. 7의 경로에서 로그인하면 같은 URL로 홈에 돌아와 그 글이 다시 변환되고, 저장은 자동으로 되지 않습니다. 사용자가 "저장"을 다시 눌러야 합니다. 그 URL을 이미 저장했다면 돌아왔을 때 "저장됨"으로 보입니다.
9. 저장에 실패하면 버튼은 "저장"으로 남고 실패를 알리는 토스트가 뜹니다.

### 저장한 글 목록

10. 로그인하지 않은 상태로 목록 주소에 들어가면 로그인 화면으로 가고, 로그인하면 목록으로 돌아옵니다.
11. 목록 위에 "저장한 글" 제목과 "N개 · 최근 저장한 순"이 보이고, 그 위에 "FEED-ME로 돌아가기" 링크가 있습니다.
12. 각 항목에는 글 제목과 "사이트명 · 저장일"(예: "Supabase Blog · 2026년 11월 17일")이 보입니다. 최근에 저장한 글이 위에 옵니다.
13. 긴 제목은 잘리지 않고 여러 줄로 감싸지며, 한국어 단어 중간에서 줄이 바뀌지 않습니다.
14. 항목을 누르면 그 글의 저장한 글 보기로 갑니다.
15. 저장한 글이 없으면 "아직 저장한 글이 없습니다" 안내와 "글 변환하러 가기" 버튼이 보이고, 버튼은 홈으로 갑니다.

### 저장한 글 보기

16. 다른 사용자의 글이거나 없는 글의 주소로 들어오면 내용을 보여 주지 않습니다. 로그인하지 않은 상태라면 로그인 화면으로 갑니다.
17. 위에 "저장한 글" 돌아가기 링크가 있고, 결과 머리에는 저장한 제목, 바이라인(저자·사이트명 규칙은 url-to-markdown 16번), 원문 링크, "YYYY년 M월 D일 저장"이 보입니다.
18. 원문 페이지를 다시 가져오지 않고 저장한 Markdown을 보여 줍니다. 원문이 바뀌었거나 사라졌어도 저장한 내용이 그대로 보입니다.
19. 미리보기/Markdown 탭과 내보내기(복사하기, 마크다운 다운로드, ChatGPT·Claude에서 열기)는 url-to-markdown 17–27번과 같은 규칙으로 동작합니다. 이 화면에는 프롬프트 입력이 없으므로 복사와 열기는 Markdown 본문만 씁니다.
20. 결과 머리의 "삭제" 버튼을 누르면 "이 글을 삭제할까요?" 확인 창이 뜹니다. 확인 창은 목록에서 사라지고 되돌릴 수 없으며 원문은 그대로라는 점을 알립니다.
21. 확인 창에서 "취소"를 누르면 아무것도 바뀌지 않습니다. "삭제"를 누르면 그 글이 지워지고 목록으로 돌아가며 "삭제했습니다" 토스트가 뜹니다.
22. 삭제한 URL을 다시 변환하면 홈에서 "저장"으로 보이고, 다시 저장할 수 있습니다.

### 접근 경계

23. 한 사용자가 저장한 글은 다른 로그인 사용자와 로그인하지 않은 사용자가 읽거나 고치거나 지울 수 없습니다. 사용자 두 명으로 확인합니다.
24. 계정이 삭제되면 그 사용자가 저장한 글도 함께 지워집니다.

### 화면 크기와 테마

25. 좁은 화면(390px 폭)에서 저장한 글 보기는 "삭제"와 복사 버튼 묶음이 제목 아래 한 줄로 내려오고, 홈은 "저장"과 복사 버튼 묶음이 같은 방식으로 내려옵니다. 어떤 action도 숨기지 않습니다.
26. 새 화면과 상태는 다크·라이트 두 테마에서 모두 읽을 수 있습니다.

## 확정된 제약과 이유

- **저장은 로그인한 사용자만 합니다.** 이미 들어간 Supabase 이메일·비밀번호 로그인과 소유자 전용 접근 방식 위에 올립니다. 익명 저장(브라우저에만 보관)은 기기를 바꾸면 사라지므로 고르지 않았습니다.
- **URL이 아니라 변환 결과 전체를 저장합니다.** 사용자가 정했습니다. 원문이 바뀌거나 사라져도 저장한 내용을 즉시 다시 볼 수 있어야 합니다. "URL만 저장하고 볼 때마다 다시 변환"은 기각했습니다.
- **같은 URL은 사용자당 하나만 저장합니다.** 사용자가 정했습니다. 목록에 같은 글이 여러 번 쌓이지 않게 합니다. "저장할 때마다 새 항목"은 기각했습니다.
- **화면 구성은 승인된 프로토타입을 따릅니다.** 저장 버튼은 결과 머리의 복사 버튼 왼쪽에 둡니다. 목록은 제목과 "사이트명 · 저장일"만 보이는 단순한 줄 목록이고, 상세에서 삭제합니다.

## 가정 (바꿔도 되는 기본값)

- 로그인 후 자동 저장은 하지 않고, 사용자가 다시 누릅니다.
- 저장을 취소하는 방법은 저장한 글 보기의 삭제뿐입니다. 홈의 "저장됨"은 누를 수 없는 상태 표시입니다.
- 저장한 글 보기에는 프롬프트 입력을 두지 않습니다.
- 목록은 한 화면에 전부 보여 주고, 페이지 나눔·검색·정렬 변경은 없습니다.
- 같은 URL 판단은 변환에 쓴 URL 문자열이 정확히 같은지로 합니다. 쿼리나 끝 슬래시만 다른 주소는 다른 글로 봅니다.
- 저장일은 사용자 브라우저 시간대 기준으로 "YYYY년 M월 D일" 형식으로 보여 줍니다.
- 저장 버튼 아이콘은 북마크, 삭제 버튼은 휴지통 아이콘과 destructive 색을 씁니다.

## 범위 밖과 이유

- 저장한 글 편집, 메모, 태그, 폴더, 검색, 공유 — 요청 범위 밖입니다.
- 저장한 글의 원문 다시 가져오기(새로 고침) — 저장 시점 내용을 보존하기로 했으므로 넣지 않습니다.
- 로그인하지 않은 사용자의 임시 저장 — 로그인 사용자만 저장하기로 했습니다.
- 프롬프트 저장 — url-to-markdown에서 프롬프트는 저장하지 않기로 정했습니다.
- 저장 개수 제한, 요청 제한 같은 하드닝 — 프로젝트 검증 예산(AGENTS.md)상 스펙이 요구하지 않은 하드닝은 범위 밖입니다.

## 남은 위험

- **저장 개수가 많아지면 목록이 길어집니다.** 페이지 나눔이 없으므로 수백 개를 저장하면 목록을 불러오고 훑기가 느려질 수 있습니다.
- **본문 크기.** 테스트한 기사의 Markdown이 34,000자 안팎이었고, 더 긴 페이지도 그대로 저장합니다. 저장 공간 한도에 걸리는 크기는 확인하지 않았습니다.
- **같은 URL 판단이 문자열 비교입니다.** 추적 파라미터만 다른 같은 글은 따로 저장됩니다.
- **url-to-markdown 스펙의 "계정, 기록, 저장 기능은 없습니다" 문장이 이 스펙과 어긋납니다.** 이 스펙이 구현되면 그 범위 문장을 함께 고쳐야 합니다.
